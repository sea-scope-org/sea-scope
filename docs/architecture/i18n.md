# Internationalization (i18n)

## Context

The product template previously served German (default) and English via an optional `{-$locale}` path segment and inline bilingual copy.
SeaScope ships English only. Keeping dual-locale machinery (cookie redirects, `hreflang`, `{ de, en }` literals) would add cost with no
product need.

## Decision

**English-only UI and URLs.** No locale path prefix, no language switcher, no i18n library.

- Public routes live directly under `src/routes/` (`/`, `/terms`, `/chat`, `/watch`, …).
- Visitor-facing strings are plain English at the call site.
- `<html lang="en">` is set in the root document.
- Display formatting (`formatDate`, `formatCurrency`, …) uses `en-US` via `Intl`. Calendar / relative-time helpers use `date-fns` `enUS`.
- Legacy `/en` and `/en/…` URLs redirect to the unprefixed path so old bookmarks and indexed English URLs keep working.

SEO canonicals and the sitemap are single-locale — see [discovery-seo.md](./discovery-seo.md). DB-backed content uses single English text
columns — see [content-model.md](./content-model.md).

## Alternatives Considered

| Option                                          | Why rejected                                                                   |
| ----------------------------------------------- | ------------------------------------------------------------------------------ |
| Keep `{-$locale}` with a single hard-coded `en` | Dead param, cookie/redirect noise, every `Link` / `seoMeta` still locale-aware |
| i18n library for a future second locale         | Premature; reintroduce path + copy strategy when a second locale is real       |
| Serve English only under `/en`                  | Forces a permanent prefix for no benefit                                       |

## Consequences

- Adding a second locale later means restoring a locale strategy (path or subdomain), copy conventions, and SEO alternates — treat that as a
  deliberate project, not a small tweak.
- Raw transport / GraphQL / upload error bodies must not reach the UI — map to English user-facing strings (e.g. `uploadErrorMessage()`).
- A static PWA manifest (`public/manifest.json`), when present, stays brand-only.

### Key files

| Concern                                             | File                                                             |
| --------------------------------------------------- | ---------------------------------------------------------------- |
| Date / currency / ISO / bytes / duration formatters | `src/shared/` (`formatDate`, `formatCurrency`, `formatBytes`, …) |
| date-fns locale (pickers / relative)                | `src/web/utils/dateFnsLocale.ts`                                 |
| Legacy `/en/*` redirect                             | `src/routes/en.index.tsx`, `src/routes/en.$.tsx`                 |
